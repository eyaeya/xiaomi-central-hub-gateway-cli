# 灯光动态公式：离线计算与接入

在用户要按一天的时间动态调亮度、色温，或需要极客版灯光表达式时读取本文。内置计算入口为 `xgg light formula`；无需访问原网页、登录米家/网关或另装计算脚本，也不会自动更新 CLI、创建文件、写变量、改规则或控制设备。

## 推荐与参数收集

用户正在设计动态灯光时，可简短说明：“可以用内置计算器生成随时间变化的亮度或色温公式，并先预览一天的变化。”复用已经给出的参数，只问影响结果的缺失项；普通开灯、关灯、设一个固定亮度的请求不需要插入这段推荐。

- **计算模式：** 色温选 `temperature`；亮度选 `brightness`；需要调整过渡陡峭程度、时间偏移或昼夜反相时选 `brightness-beta`。
- **纬度：** 接受 −75° 至 75°，南纬用负数。不默认使用网页示例城市或某个家庭地址；用户给出地点但未给纬度时，先确认采用的纬度。此能力不需要精确家庭地址或经度。
- **上下限：** 色温为整数 K，计算器范围 2000–8000；亮度为整数百分比 0–100；必须 `min < max`。这些是计算器允许的输入，不是任何灯具的能力证明。让用户确定希望的低值和高值；不照搬网页默认值。
- **目标设备：** 只算公式时可先不选设备。要接入实际灯光时，先用目标设备的 `device spec` 核对真实属性、单位、可写权限、值域、步进及 value-list，再确认期望上下限都能落到合法值。不能仅凭名称断定支持亮度或色温。
- **Beta 可选项：** 默认 `speed=0.3`、`smoothness=0.9`、`offset-minutes=0`、不反相。没有定制诉求时说明使用默认值即可，不要求用户逐个选择全部旋钮。
- **预览：** 用户需要具体某一天的数值时使用明确的 `YYYY-MM-DD`，解释这是网关当地钟表时间；不从执行主机日期或时区猜测用户的预览日期。

已有规则配置或启用授权仍按原范围执行；仅请求计算公式不表示授权写入或启用自动化。

## 命令与输出

本能力是当前源码新增功能，尚未包含在已发布的 v3.1.0 中。先检查实际入口的 `light formula --help`。公开源码 checkout 在 `pnpm install && pnpm build` 后使用 `node packages/cli/dist/cli.js`；开发仓库可用 `pnpm --filter @xgg/cli dev`。下面的 `xgg` 指含此功能的构建，不要重装旧版全局 npm 包后声称已获得新能力。

以下纬度和数值只是示例：

```bash
# JSON，适合 Agent：公式、归一化参数、单位、建议周期和模型警告
xgg light formula temperature --latitude 23.129 --min 3200 --max 5400

# 指定日期的全天预览，60 分钟一个样本
xgg light formula brightness --latitude 23.129 --min 10 --max 100 \
  --date 2026-10-15 --sample-minutes 60 --pretty

# Beta：正偏移让曲线提前，反相让夜间高、白天低
xgg light formula brightness-beta --latitude 23.129 --min 10 --max 80 \
  --speed 0.3 --smoothness 0.9 --offset-minutes 30 --invert

# 仅取得单行表达式，并用已有语法检查器独立检查；两条命令均不改设备
LIGHT_EXPR="$(xgg light formula brightness --latitude 23.129 --min 10 --max 100 --expression-only)"
xgg rule expr-check "$LIGHT_EXPR"
```

默认 JSON 包含 `ok`、`mode`、`unit`、`parameters`、`expression`、`recommendedIntervalSeconds`、`warnings` 和 `sourceUrl`。指定 `--date` 后另有 `preview`：样本的 `time/value`、样本最小/最大值、`solarDayState` 及模型近似日出/日落（午夜起秒数；极昼/极夜为 null）。`preview.minimum/maximum` 是采样所得，不是所有连续时刻的极值证明。

`--pretty` 给人阅读；`--expression-only` 只输出表达式与换行，两者互斥。只提取表达式会看不到 JSON 中的模型警告，Agent 仍应向用户说明相关边界。`--sample-minutes` 默认 30，显式使用时必须同时提供日期；取值须为 1–1440 内且能整除 1440 的整数。样本从 00:00 开始，不含次日 24:00。日期只控制预览，生成的公式仍在网关运行时读取当天日期和时钟。

Beta 专属参数只允许用于 `brightness-beta`：速度 0.1–20、平滑度 0.1–5、偏移 −180 至 180 分钟，`--invert` 反相。无效日期、非法数值或不支持的参数会报错，不返回旧公式作为替代。

## 接入灯光规则

先展示选定参数和预览，核对目标 spec，再在用户已授权的配置范围内接入现有规则编写流程：

```text
onLoad → loop（建议每 30 秒） → varSetNumber（生成的 expression）
                                → deviceOutput（引用 number 变量）
```

`varSetNumber` 需要已存在的 number 变量，用 `--var-scope`、`--var-id` 指定目标，并把生成的完整字符串作为一个带引号的 `--expr` 参数传入。先计算再输出，不能让设备动作与变量计算并行而读到旧值。生成表达式本身不会周期执行；周期来自规则的 loop。需要一启用就得到新值时，另行设计明确的初始化事件路径并查日志证明，不能假定 loop 的第一 tick 时序。

亮度输出单位固定为百分比，色温输出固定为 K。**百分比不是设备原始亮度值。** 目标若使用原始整数范围，先确认该属性的百分比映射，再增加独立转换；不能仅因 `[min,max]` 就假定线性比例。目标有步进时，按 spec 的起点对齐步进，量化后限制在用户范围内的合法端点，并检查边界值；公式的整数取整不自动满足设备步进。例如 K 值为整数仍可能不符合 100 K 的步进。

目标若有 `value-list`，不能把连续曲线直接用作变量输出：按受支持的枚举设计离散分支与原生 literal，或改选真正支持连续调节的属性。亮度 0 也不保证等价于关灯，开关状态要按用户意图单独处理。写亮度/色温是否会点亮已关闭灯具取决于设备；需要“只在已开灯时调整”的规则应增加状态门并实际验证。

创建或编辑规则仍使用快照、禁用草案、变量存在性与当前 spec 校验。构图后先 `rule validate --rule-id <rid> --spec-aware`、strict lint，已获授权才启用；用 `rule logs`、变量回读和设备 `get/watch --source device` 核对结果。保留测试前原值，结束后按已授权范围停止测试、恢复并直读验证。只有离线计算或静态校验时，不报告“灯具已验证正常”。

## 计算模型与来源差异

数学行为来源于 [Jimmy Website 的 MIoT Geek 工具](https://lzj.ac.cn/tools/iot/miot-geek)。xgg 独立实现计算，不复制网页组件、脚本或图片。原网页对 Beta 标注未经作者实测；xgg 的公式/预览测试也不能替代目标灯具的物理验收。

三个模式共用近似日照曲线：`D = month()*30 + date()`，赤纬近似 `23.44*sin(2*pi()/365*(D-81))`，以当地钟表 12:00 为对称中心；标准模式使用 logistic 过渡，Beta 可调斜率、平移与反相。没有经度、真实年内日序、均时差或夏令时校正，`approximateSunrise/approximateSunset` 只表示这个模型的参考时刻，不能当作天文日出日落预报。

- 生成数值是向下取整后的曲线值，`min/max` 是界限，未必精确达到。例如上限 100% 不保证中午恰好等于 100%。预览采用与公式一致的 `floor`，而原网页图表的取整与输出公式不同。
- xgg 用 `abs(t)` 改写源公式，修复正午除零；对反余弦输入、分母和指数做有界处理，避免极昼/极夜及临界日期输出非有限值。这是数值修正，极区曲线是有界延伸，不是已验证的极区天文模型：极夜可能在正午出现窄峰，极昼可能在午夜出现窄谷。高纬度配置先预览，不假定极昼/极夜就是全天恒定输出。
- 保留网页的 Beta 偏移方向：正数提前、负数延后；不进行跨午夜循环平移，偏移后可能在午夜跳变。`speed` 与 `smoothness` 实际相乘，提高任一项都会使过渡更陡，不能把“平滑度越大”解释为必定更缓。
- xgg 放宽网页纯 UI 的最小跨度限制，并允许标准亮度低至 0%；真实设备仍以自己的 spec 为准。xgg 统一建议 30 秒重算；原网页 Beta 提示 60 秒，周期也需按实际设备与规则负荷选择。

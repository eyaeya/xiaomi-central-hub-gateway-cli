# Lighting v3.2.0 pre-publication verification

Date: 2026-10-15. Scope: offline formula generation, consolidated brightness
controls, Agent Skill integration and public package preparation. This supersedes
the earlier three-mode prototype's acceptance record for the current interface.

## Accepted behavior

- Exactly two modes: temperature and brightness. Brightness uses
  `k=4.5*speed/M`, default speed 1, with independent offset and inversion.
  Default samples remain 45 at 06:00, 89 at 09:00 and 99 at noon for the recorded
  sample latitude/range/date. Temperature remains unchanged.
- Source-derived numerical tests and independent expression evaluation cover
  noon, extreme parameters, polar boundaries, dates, offsets and inversion.
- Formula parser errors use CONFIG / exit 5 and offline help. Removed
  smoothness input explains speed/default 1; it is not a registered option.
  Independent review found and then confirmed this error-context repair.
- Network traps and update exclusion tests pass. Formula generation does not
  authenticate, create snapshots, or modify devices, rules or variables.
- Independent Skill invocation chose speed 0.5 and offset 30 for a gentler
  curve advanced by half an hour, with 24 hourly samples and no algorithm-choice
  question or device operation.

## Final validation

- Root `pnpm check`: 2,062 unit tests and 333 contract tests pass; one existing
  contract test is skipped. Harness, leak guard, fixtures and probes pass.
- Public frozen-lockfile install and `pnpm check`: 776 Node tests and 392
  cloud-related Vitest tests pass.
- The first Public run failed in an unchanged 100 ms lease-fence assertion
  after its NOT_CONFIRMED assertion had already passed. The isolated file
  passed five tests, and the original full command subsequently passed. No
  lease behavior or timing test was relaxed for this feature. Original and
  rerun logs are retained locally.
- `pnpm pack:release`: both 3.2.0 tarballs pass the file allow-list; no reference
  snapshots, docs or private probe artifacts enter npm. CLI depends on
  `@eyaeya/xgg-core` version `^3.2.0` in the packed manifest.
- Isolated installation passes version/help, both modes, default and advanced
  brightness, SDK equivalence, expression validation and obsolete-input
  rejection checks. Canonical Skill and installed package Skill match exactly.
- Canonical Skill marker:
  `sha256-2e405173f7178df0e82d2a0be100cae1c8eac157f9c56631fa43465f0ebc313b`.

## Evidence boundaries

Read-only live discovery verified the unchanged numeric-expression node shape.
No generated formula was enabled on a real lamp. The fixed-noon calendar model,
polar extension and non-wrapping offsets retain their documented limitations.
PR merge, registry publication and default npm-page presentation are separate
post-publication checks; this record does not claim they have happened yet.
